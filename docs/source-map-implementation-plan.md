# Source Map 当前设计

这份文档记录当前已经落地的 Source Map 设计，而不是早期实施计划。项目当前的核心目标是：在 ECMAScript 语法兼容性诊断中提供 original source 定位，但不让 Source Map 参与“某个语法是否兼容”的判断。

## 领域边界

Source Map 是诊断增强层：

- `SyntaxFeatureDetector` 只负责从输入文本里识别 `SyntaxFeatureId` 和 `SyntaxFeatureUsage`。
- `SyntaxFeatureUsage::span` 始终表示 generated 文件里的 UTF-8 byte span。
- `SourceMapResolver` 尝试把 generated 位置映射到 original source。
- `SyntaxCompatDatabase` 根据 `SyntaxFeatureId` 和目标运行时给出支持规则。
- `CompatAnalyzer` 聚合检测结果、Source Map 状态和目标兼容性状态，形成 `CompatReport`。

因此，即使 Source Map 缺失或某个位置无法映射，兼容性诊断仍然成立，只是 original source 字段会显示不可用原因。

## 当前流程

```text
SourceFile
  -> SyntaxFeatureDetector
  -> SyntaxDetectionResult(path, Vec<SyntaxFeatureUsage>)
  -> SourceMapResolver
  -> SourceMapping
  -> SyntaxCompatDatabase + evaluate
  -> CompatReport
```

报告中的一条 `CompatDiagnostic` 以单个语法 usage 为中心，聚合该 usage 在多个 target 上的非 Supported 状态。这样避免把 `usage x target` 展开成大量重复诊断。

## Source Map 发现规则

当前 resolver 支持两种发现方式：

- 显式 `sourceMappingURL` 注释。
- 没有显式引用时，回退到相邻 `.map` 文件。

显式引用优先级更高。如果文件中出现多个冲突的显式引用，resolver 会返回歧义错误，并在报告中体现为 `SourceMapUnavailable::AmbiguousReference`。

## Source Map 加载规则

当前默认 loader 是组合 loader：

- `FileSourceMapLoader` 负责本地 `.map` 文件。
- `DataUriSourceMapLoader` 负责 `data:` URI。
- `DefaultSourceMapLoader` 按 reference 类型分派给具体 loader。

loader trait 的存在是为了保持边界清晰：resolver 只表达“要加载哪个 Source Map”，具体怎么读取由 loader 实现。后续如果需要 HTTP loader，可以新增实现类，而不需要修改 detector 或 analyzer 的领域模型。

## 位置模型

项目里同时存在 generated 位置和 original source 位置：

- `SourceSpan`：generated 文件中的 UTF-8 byte span，来自 parser span。
- `SourcePosition`：generated 文件中的零基行列，用于 Source Map 查询和展示。
- `SourceIdentity`：Source Map `sources` 中的代码源身份，可能是文件路径，也可能是虚拟源名。
- `SourceLocation`：Source Map 映射成功后的 original source、起点和终点。
- `SourceMapping`：单个 usage 的映射结果，可能是 `Mapped`、`Unavailable` 或 `NotResolved`。

`SourceMapReference` 表示产物文件如何引用 Source Map；`SourceIdentity` 表示 Source Map 里的 original source。前者针对构建产物，后者针对源码来源，两个概念不要合并。

## 已实现能力

- 解析 Source Map v3。
- 处理 `sourceMappingURL`。
- 没有显式引用时查找相邻 `.map` 文件。
- 支持本地文件 Source Map。
- 支持 data URI Source Map。
- 支持 `sources` 和 `sourceRoot` 合成 original source identity。
- 将 generated byte offset 转换为 Source Map 查询需要的行列。
- 单个 generated 位置无法映射时，保留 generated 位置并给出不可用原因。

## 当前非目标

- HTTP Source Map 加载。
- Source Map response header。
- index source map。
- 多级 Source Map 链路。
- 根据 original source 内容重新检测语法。
- 运行时 API 兼容性检测。

## 设计约束

- 兼容性事实来自 generated 输入文件中仍然存在的语法，不来自 original source。
- `SyntaxFeatureUsage::span` 不被 Source Map 覆盖。
- Source Map 状态分为文件级状态和 usage 级状态：文件级 resolved 不代表每个 usage 都能映射成功。
- original source 不一定是本地文件路径，调用方展示时必须处理虚拟 source。
- Source Map 错误不应吞掉语法检测结果。

## 后续可扩展点

- 新增 HTTP loader，实现 `SourceMapLoader`。
- 支持 Source Map response header，把 discovery 从文件内容扩展到外部元数据。
- 支持 grouped report 或 CI summary，但应当基于 `CompatReport` 派生，不改变 detector 的职责。
- 如果未来要做运行时 API 检测，应新增独立的 runtime API detector 和领域模型，不复用 `SyntaxFeatureId`。
